# CJ ONE 시연용 프론트엔드

부하테스트 시연영상에 쓰는 화면 묶음입니다. 화면은 세 종류.

| 화면 | URL | 역할 |
| --- | --- | --- |
| 매장 POS 단말 | `/?view=pos&tenant=cgv` | 사람이 실제로 누르는 요청 **1건**. earn / use / balance API를 그대로 호출 |
| 에이전트 실행 콘솔 | `/?view=console` | 운영자 메인. 쿼터 재분배 → 이상탐지 → 진단 에이전트가 무엇을 보고 무엇을 했는지 |
| 진행자 패널 | `/?view=control` | 시연 순서·k6 명령. **녹화 화면에 넣지 말 것** |

`/` 로 들어가면 위 창들을 띄우는 런처가 나옵니다.

## 실행

```bash
npm install
npm run dev

# 에이전트 콘솔(메인)
http://localhost:5173/?view=console
# CGV POS
http://localhost:5173/?view=pos&tenant=cgv
# OLIVEYOUNG POS
http://localhost:5173/?view=pos&tenant=oliveyoung              
```

`.env.local` 은 **안 만들어도 됩니다.** 아래 "API 키" 참고.

## 연결 모드 — 목업이 기본값

백엔드가 아직 안 붙어 있어서 **기본은 목업 모드**입니다. 아무 설정 없이 적립·사용·조회가 전부 동작하고,
잔액도 실제로 오르내립니다. 시연 리허설을 지금 바로 할 수 있어요.

바꾸는 곳: POS 상단 칩(또는 런처의 같은 버튼) → `연결 설정` → **목업 / 실서버**.
선택은 브라우저에 저장되므로 코드나 `.env` 를 안 건드려도 됩니다.

### 목업이 그냥 성공만 돌려주지 않는 이유

시연의 핵심은 **부하 상태에 따라 응답이 달라지는 것**입니다.

| 상태 | 지연 | 응답 |
| --- | --- | --- |
| 평상시 | 28~62 ms | 201 / 200 |
| 부하 토글 ON | 620~880 ms | 28% `503 upstream saturated`, 16% `429 quota exceeded`, 나머지 성공 |

POS 하단 부하 토글은 **그 창의 테넌트에만** 걸립니다. CGV 창만 켜면 CGV만 느려지고 실패하며,
올리브영 창은 그대로 28ms로 성공합니다 — 이 대비가 격리 주장의 장면입니다.

목업 응답은 로그에 `MOCK` 태그가 붙습니다. 실제 호출과 절대 헷갈리지 않게 해뒀어요.
잔액을 되돌리려면 연결 설정의 `잔액 초기화`.

## API 키 — 세 가지 경로

키가 없어도 버튼은 눌립니다. 요청이 나가고 `401/403` 이 로그에 그대로 찍혀요. 흐름을 막지 않습니다.

**① 개발 서버가 자동으로 붙여줌 (기본)**
`npm run dev` 가 뜰 때 개발 서버가 Secrets Manager 에서 키를 읽어두고,
프록시 단계에서 `x-tenant-id` 를 보고 `x-api-key` 를 끼워 넣습니다.
**브라우저에는 키가 안 내려갑니다.** AWS 프로필만 잡혀 있으면 아무것도 안 해도 동작해요.

```bash
export AWS_PROFILE=capstone-terraform   # 기본값이라 생략 가능
aws sso login --profile capstone-terraform   # 세션 만료됐을 때만
```

**② 화면에서 직접 붙여넣기**
POS 상단의 `API 키 설정` 칩(또는 런처의 같은 버튼)을 누르면 패널이 열립니다.
테넌트별로 키를 붙여넣으면 이 브라우저에만 저장되고 즉시 반영됩니다. 서버 키보다 우선합니다.

**③ `.env.local`**
`cp .env.example .env.local` 후 `VITE_*_KEY` 를 채우는 옛날 방식. 여전히 동작합니다.

> 상태 확인: 패널 상단이 `4/4 준비됨` 이면 끝. `키 다시 불러오기` 로 재시도할 수 있고,
> 실패하면 원인(aws CLI 없음 / SSO 만료 등)과 실행할 명령이 그 자리에 뜹니다.
> 디버깅용 엔드포인트: `curl localhost:5173/__dev/keys`

## 화면

지금 살아 있는 건 둘입니다.

- `/?view=console` — 에이전트 실행 콘솔 (메인). **키 없이도 전부 동작**
- `/?view=pos&tenant=cgv` — CGV POS 단말

`src/views/DemoControl.tsx` (진행자 패널)는 라우팅에서 뺐습니다. 파일은 남아 있으니 필요하면
`App.tsx` 에 다시 연결하거나 지우세요. 다른 테넌트 POS 는 `?tenant=oliveyoung` 처럼 주소로는
여전히 열립니다 — 런처에서만 감췄습니다.

## 설계 메모 — 왜 이렇게 짰는지

**1. POS는 부하 생성기가 아닙니다.**
3,600 QPS를 사람이 클릭으로 만들 수 없습니다. 실제 부하는 `k6/` 스크립트가 만들고,
POS는 *"폭주 중에도 올리브영 손님은 51ms에 적립되는데 CGV 손님은 실패한다"* 를
눈으로 보여주는 창구입니다. POS 하단의 부하 토글은 **표시용**이고, 실제 부하는 터미널에서 돕니다.

**2. 콘솔은 리플레이입니다.**
에이전트 반응은 4.2초, POS 클릭은 1초, 부하 램프는 2분 — 시간 축이 안 맞습니다.
실시간 스트림만 있으면 진행자가 타이밍을 통제할 수 없어요.
그래서 끝난 run을 시간축으로 되감아 재생합니다. 재생바의 눈금은 이벤트 마커라 클릭하면 그 시점으로 점프합니다.

**3. 콘솔에는 조작 버튼이 없습니다.**
에이전트가 자동으로 하는 게 주장인데 승인 버튼이 있으면 앞뒤가 안 맞습니다.
진행용 컨트롤은 `/?view=control` 로 분리했습니다.

**4. trace id 로 두 창을 잇습니다.**
POS가 보내는 요청마다 `x-trace-id` 를 달고, 같은 값을 POS 로그와 콘솔의 "실제 POS 호출"에 함께 띄웁니다.
*"지금 제가 누른 이 요청이 저기 저 줄입니다"* 라고 말할 근거가 생깁니다.
백엔드가 이 헤더를 안 봐도 상관없습니다.

## 에이전트 이벤트를 실제 데이터로 바꾸려면

지금은 `src/lib/mockRun.ts` 가 타임라인을 만들어 재생합니다. **숫자는 전부 예시값입니다.**

실제 에이전트가 이벤트를 남기기 시작하면:

1. `.env.local` 에 `VITE_AGENT_SOURCE=live` 와 `VITE_AGENT_EVENTS_URL=...` 를 채우고
2. 그 URL이 `src/lib/types.ts` 의 `RunTimeline` 모양으로 응답하게 만들면 끝입니다.

화면은 데이터가 어디서 왔는지 모릅니다. `AgentEvent.stage` 는
`trigger → observe → decide → act → verify` (쿼터 재분배)와
`anomaly → evidence → rootcause → recommend` (진단) 두 벌입니다.

## 아직 안 채운 것

- SLO 임계값이 `300ms` 하드코딩입니다 — SLI/SLO 설계 문서 확정값으로 교체하세요 (`mockRun.ts` 의 `SLO_MS`).
- p99 시계열 차트가 없습니다. 콘솔 왼쪽은 현재값만 보여줍니다. 곡선이 필요하면 Grafana 패널을 iframe으로 얹는 쪽이 쌉니다.
- 회원 잔액은 `balance` 응답의 `balance` 필드를 읽습니다. 실제 응답 스키마가 다르면 `src/lib/api.ts` 의 `fetchBalance` 를 고치세요.
